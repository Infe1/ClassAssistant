## 需要修正的两条

### ❌ D3-① 「GBK 编码」不成立

**报告原文**：「中文注释为 GBK 编码，UTF-8 工具链下显示乱码」

**实测**：

```
$ python -c "open('requirements.txt','rb').read().decode('utf-8')"
  → 成功
$ ... .decode('gbk')
  → 失败: 'gbk' codec can't decode byte 0xaf in position 38
$ od -c 前 200 字节
  344 270 212 350 257 276 ...   ← 0xE4 0xB8 0x8A = UTF-8 的「上」
```

**结论**：文件是**合法 UTF-8（无 BOM）**，并非 GBK。

**为什么会误判**：Windows PowerShell 5.1 默认按 **GBK(936)** 读文件，
用 `Get-Content` 打开 UTF-8 中文文件必然显示乱码 —— **这是读取端编码假设的问题，
不是文件编码错误**。用 `Get-Content -Encoding UTF8` 或任何 UTF-8 工具读均正常。

⇒ 该项**建议撤销**；若确有显示需求，可给文件加 BOM（但会与项目其他文件不一致，
不推荐）。

### ⚠️ F3 「常驻动画」的归类需收窄

**报告列出三处**：

| 位置 | 实际性质 | 是否常驻 |
|---|---|---|
| `index.css:267-276` `corner-sheen` | 主窗口顶部流光，`5s infinite` | ✅ **确为常驻** |
| `index.css:87-94` `startup-glow` | **启动页**（splash）背景 | ❌ 仅 splash 存在时 |
| `index.css:96-99` `startup-ring` | **启动页**光环 | ❌ 同上 |
| `index.css:105-113` `startup-dot` | **启动页**闪烁点 | ❌ 同上 |

`splash` 窗口关闭后这些节点不再渲染，**不构成"全程"负载**。

⇒ 「常驻 GPU 占用」这一结论**对主窗口成立**（`corner-sheen` + `.corner-art::before/after`
的 `filter: blur(7px)`），但**引用 startup 动画作为佐证不准确**。
