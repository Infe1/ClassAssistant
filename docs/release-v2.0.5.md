## 二、修复明细

### B1 🔴 设置面板改配置后不生效

**现象**：在设置面板改 `LLM_MODEL` / `LLM_API_KEY` / `LLM_TIMEOUT` 并保存后，
提示「设置已保存并已同步到当前进程」，但实际不生效，必须重启后端。
排错时容易被引向网络或服务商方向。

**根因**：`LLMService.__init__` 一次性读取三项配置并构造 `AsyncOpenAI`，
实例分散在 `rescue_router`（模块级）、`monitor_service`、`summary_service` 三处。
设置保存只做了 `load_dotenv(override=True)`，已构造的实例仍持有旧配置。
（对照：`SUMMARY_MAX_TOKENS` 走 `resolve_summary_max_tokens()` 每次重读，所以它是生效的。）

**处理**：`self.client` 由普通属性改为 **property**，每次访问时比对
`(base_url, api_key, model, timeout)` 四项签名，有变化才重建客户端。
三处实例**无需任何改动**即自动感知配置变化。

**验证**：改 `LLM_MODEL` 后访问 `client` → 实例 id 变化（重建）；
连续访问且配置未变 → 实例 id 相同（复用）。

---

### B2 🟡 `.ppt` / `.doc` 声称支持但必然失败

**现象**：`ALLOWED_EXTENSIONS` 含 `.ppt` / `.doc`，用户上传后必然失败，
且只得到一句笼统的「文件解析失败」。

**根因**：`parse_material` 把 `.ppt` 交给 python-pptx、`.doc` 交给 python-docx，
而这两个库**只支持 OOXML**（`.pptx` / `.docx`）。传入 Office 2003 二进制老格式时，
库在打开阶段即抛 `PackageNotFoundError` 一类异常。

**处理**：
- 从 `ALLOWED_EXTENSIONS` 移除 `.ppt` / `.doc`；
- 新增 `LEGACY_EXTENSIONS` + `LEGACY_HINT`，命中老格式时直接返回
  「不支持 .ppt 格式（Office 2003 老格式）。请先用 Office / WPS 打开并『另存为』
  .pptx 或 .docx，再上传。」

---

### B3 🟡 上传临时文件失败不清理 + 固定文件名并发冲突

**现象**：解析失败时 `data/temp_upload.pdf` 一类文件残留；两个并发上传同后缀文件
会写入同一路径互相覆盖。

**根因**：`temp_path = os.path.join(DATA_DIR, f"temp_upload{ext}")` 为固定名，
且清理只写在成功路径上。

**处理**：改用 `tempfile.mkstemp(suffix=ext, dir=DATA_DIR)` 生成唯一文件名；
清理移入 `finally`，成功与失败路径都会执行。

---

### B4 🟡 最近转录可能混入上一节课内容

**现象**：救场 / 进度总结的上下文里出现上一节课的残留内容。

**根因**：转录行时间戳只有 `HH:MM:SS`，`get_recent_transcript` 用
`strptime(...).replace(year=now.year, month=now.month, day=now.day)` 把每行都当「今天」。
转录文件里若残留旧记录，其时间只要落在「最近 N 分钟」窗口内就会被取走。

**处理**：**不改时间戳格式**（那会贯穿写入、去重、前端展示三处，改动面大），
改为在读取侧定位**最后一个**「`=== 课堂记录 开始于 ... ===`」标记，只在其之后筛选。
找不到标记时（旧格式文件）行为与之前一致。

**验证**：构造含两个会话、各放一条 1 分钟前时间戳行的文件，
结果只返回第二次会话内容，第一次会话的残留行被过滤。

---

### C1 🟡 转录落盘全量重写（O(n²)）

**现象**：长课后段磁盘 IO 可感知；每次 flush 发生在 ASR 回调的锁内。

**根因**：`_flush_transcript_file` 每次都用 `"w"` 重写整个文件，
而它被每条最终转录行触发。2 小时课程约 1500 行时，总写入量接近行数的平方。

**处理**：新增 `_flushed_text` 记录上次落盘的完整文本；
`_flush_transcript_file` 先构建 `body`，然后判断：

- `body` 以上次内容为**前缀**（纯追加）→ 只 `append` 差量；
- 否则（会话开始/结束标记、滚动摘要更新、行被合并或删除、首次落盘）→ 整文件重写。

因为判据是「内容前缀」，**所有会改写头部或中间内容的场景自动回落到全量重写**，
无需在 6 个调用点做区分。两条路径产出的文件内容完全一致。

**验证**：临时文件测三条路径 —— 首次落盘结构完整、追加无重复、头部变化时摘要块正确插入。

---

### C2 🔵 去重相似度比对在长文本上偏重

**处理**：加长度预筛。`SequenceMatcher.ratio()` 的数学上界为 `2s/(s+l)`，
令其 < 0.88（判定阈值）解得 `s/l < 0.786`，故 `s/l < 0.78` 时必然不相似，直接跳过。

**验证**：50000 组随机文本对穷举比对，**因预筛漏判的高相似度组合 = 0**，
与原逻辑**完全等价**。
