# v2.0.3 发布说明

> 发布日期：2026-09-22
> 上一版本：v2.0.2
> 提交范围：`157c5a8` → `8298497`

本次为**修复版本**，主要解决「AI 追问偶尔不回答」与「任务栏图标模糊」两个问题。

---

## 🔧 修复

### 1. AI 追问偶尔返回「当前没有可用回答」

**现象**：追问时界面显示 `当前没有可用回答。`，或长时间停在「AI 思考中...」，
按钮一直不可点，只能重启应用。

**根因一 —— 空回复的原因被合并，且无任何日志。**

该文案仅在两个追问接口中产生，含义是「HTTP 200 正常返回，但正文为空串」
（若接口报错会显示「课堂追问失败」，网络异常会显示「LLM 调用失败」，两者均未出现）。

正文为空实际有三种互不相同的情况，此前全部被合并成同一句话、日志里不留任何记录：

| 情况 | 真实原因 |
|---|---|
| 模型返回 `tool_calls` 而无正文 | 该模型是 Agent 型、想调工具，而本服务未实现工具执行 |
| 只返回思维链（`reasoning_content`） | 追问 `max_tokens` 仅 800，被思维链吃光 |
| 两者都空 | 模型拒答 / `finish_reason=length` |

**处理**：

- 新增统一的正文抽取逻辑，**按上述三种情况分别输出 ERROR 日志**，
  日志会写明是哪种原因、`finish_reason` 是什么，便于直接定位。
- 追问调用点补上 `logger.exception`。此前调用失败时日志中**没有任何记录**。
- 界面文案改为可操作提示，同时保留原有重试能力。

**根因二 —— 请求可能被无限期挂起。**

两个实测事实：

- 前端使用的 `fetch` **原生不支持超时**
- `AsyncOpenAI` SDK 默认超时 **600 秒**，且默认重试 2 次
  ⇒ 最坏情况 `3 × 600 = 1800 秒`（30 分钟）

一节课内若某个请求变慢，界面会长时间无响应，按钮全程不可点。

**处理**：

- 后端超时收窄至 **60 秒**（可用 `.env` 的 `LLM_TIMEOUT` 调整，范围 5–600），
  并关闭 SDK 内置重试，避免「超时 → 重试 → 再超时」把卡顿放大数倍。
- 前端新增请求超时（普通请求 90 秒、课后总结 180 秒），全部 **24 处**请求统一接入。
- 超时后给出明确提示，并把提问内容放回输入框，可直接重发，无需重新输入。

### 2. 任务栏图标模糊

**根因**：`icon.ico` 缺少高 DPI 所需的尺寸 ——

```
旧：16 / 32 / 128 / 256
```

Windows 按屏幕缩放比例挑选位图，缺的正是最常用的那几个：
**125% 需 40px、150% 需 48px、200% 需 64px** —— 旧文件里都没有，
只能拿 32×32 放大显示，因此必然模糊。

**处理**：补全为 7 个尺寸，并统一改为 PNG 格式（体积更小、缩放更清晰）：

```
新：16 / 24 / 32 / 48 / 64 / 128 / 256
```

> 注：经比对 v1.3.0 / v2.0.1 / v2.0.2 三个发布版的内嵌图标，**尺寸与字节完全一致** ——
> 该问题自 v1.3.0 起就存在，并非新版本引入。

## 💡 优化

- **新增 prompt 前缀缓存命中日志**。
  调用日志中会输出 `[LLM缓存] <接口> | 命中 N / 输入 M (P%)`，
  用于判断「把不变内容（课程资料、系统提示词）放在请求头部」的策略是否生效。
  兼容 DeepSeek 与 OpenAI 两种上报字段；服务商不支持该字段时静默跳过，不影响正常流程。

- **调整请求内容顺序**，将整节课不变的「课程资料」前置、每次变化的转录后置，
  使公共前缀稳定，以命中服务端前缀缓存（DeepSeek 命中价约为未命中的 1/10）。
  仅调整段落顺序，语义未变。

## 🔍 排查指引

若今后再遇到 AI 不回答，直接查看后端日志：

| 日志内容 | 含义 |
|---|---|
| `[LLM空回复] ... 返回了 N 个 tool_calls` | 模型为 Agent 型，需更换模型 |
| `[LLM空回复] ... 只返回了思维链` | `max_tokens` 不足，需调大 |
| `[LLM调用失败]` | 网络、鉴权或额度问题 |
| 界面提示「请求超时」 | 后端长时间未响应，检查后端是否在运行 |
