# 前端请求栈溢出：排查与修复

> 状态：**已定位根因并修复**（2026-09-23）
> 影响版本：**2.0.3 单版本**（`daac50e` 引入，2.0.2 及之前无此问题）
> 修复版本：**2.0.4**
> 影响范围：**前端全部 24 处后端请求**，应用整体不可用

## 一、现象

用户把原有的 `.env` 放进新版本后启动，**界面直接不可用**，窗口中显示红色报错，
用户记得关键字是 **"exceed"**。

初判方向是「`.env` 兼容性」——因为用户恰好同时更换了 `.env`。
**但该判断是错的**（见第四节）。

## 二、根因：`fetchWithTimeout` 递归调用自身

`app-ui/src/services/api.ts` 第 51 行：

```typescript
/** 带超时的 fetch —— 所有后端请求都应经由它发出。 */
async function fetchWithTimeout(
  url: string,
  init: RequestInit = {},
  timeoutMs = DEFAULT_TIMEOUT_MS
): Promise<Response> {
  const { signal, clear } = withTimeout(init.signal ?? undefined, timeoutMs);
  try {
    return await fetchWithTimeout(url, { ...init, signal });   // ← 调用了自己
  } finally {
    clear();
  }
}
```

函数内部调用的不是原生 `fetch`，而是**它自己**。于是：

1. 每次调用都重新进入函数，创建新的 `AbortController` 与 `setTimeout`
2. 调用栈无限增长
3. 最终抛出 **`RangeError: Maximum call stack size exceeded`**

**这就是用户看到的红色 "exceed"。**

### 正确的写法

```typescript
return await fetch(url, { ...init, signal });
```

一个词的差别，语义从「发请求」变成「无限递归」。

## 三、为什么编译期查不出来

`npx tsc --noEmit` **EXIT=0，完全通过**。

原因：`fetchWithTimeout(url, init, timeoutMs?)` 与它自身的调用签名**完全匹配** ——
参数类型一致、返回类型一致，TypeScript 没有任何理由报错。

这类错误属于**运行期语义错误**，静态类型系统无法覆盖。
本次修复后已在代码处加注释，防止再次误写。

## 四、与 `.env` 无关（重要澄清）

排查中逐项验证了 `.env` 相关假设，**全部排除**：

| 假设 | 结论 |
|---|---|
| 新增的 `LLM_TIMEOUT` 没有默认值 | ❌ `resolve_llm_timeout()` 空值回退 `DEFAULT_LLM_TIMEOUT = 60.0` |
| `SUMMARY_MAX_TOKENS` 没有默认值 | ❌ 空值回退 `DEFAULT_SUMMARY_MAX_TOKENS = 20000` |
| `.env` 缺项导致启动失败 | ❌ 项目内 19 个 `os.getenv` 调用**全部带默认值**，无一裸读 |
| `.env` 编码/BOM 问题 | ❌ 文件为正常 UTF-8 |

**决定性证据**：该 bug 位于**所有请求的必经之路**上，与 `.env` 内容无关 ——
**任何 `.env`（包括打包自带的 `.env.example` 副本）都会同样崩溃**。
用户「换 `.env` 后坏掉」只是时间上的巧合。

## 五、影响范围

`fetchWithTimeout` 被 **24 处**业务请求调用，覆盖：

- 上传 PPT / 解析
- 开始 · 停止 · 暂停 · 恢复监控
- 救场 · 救场追问
- 课堂追问 · 课后总结（catchup）
- 读写关键词 · 引用文件 · 读写设置
- Prompt 选择与草稿
- 写入 ASR 文本

⇒ **整个应用完全不可用**，与用户描述一致。

### 自递归检测脚本（可复用）

```python
import ast, io, os, re

# Python：用 ast 精确定位函数体内的自调用
for dp, dns, fns in os.walk('api-service'):
    dns[:] = [d for d in dns if d not in ('.venv', 'build', 'dist')]
    for fn in fns:
        if not fn.endswith('.py'): continue
        p = os.path.join(dp, fn)
        try: tree = ast.parse(io.open(p, encoding='utf-8').read())
        except Exception: continue
        for node in ast.walk(tree):
            if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
                for sub in ast.walk(node):
                    if (isinstance(sub, ast.Call) and isinstance(sub.func, ast.Name)
                            and sub.func.id == node.name):
                        print(f'[自递归] {p}:{node.lineno} {node.name}()')

# TS：提取函数体（大括号配平）后检查自调用
for dp, dns, fns in os.walk('app-ui/src'):
    dns[:] = [d for d in dns if d not in ('node_modules', 'target', 'dist')]
    for fn in fns:
        if not fn.endswith(('.ts', '.tsx')): continue
        p = os.path.join(dp, fn)
        src = io.open(p, encoding='utf-8').read()
        for m in re.finditer(r'(?:async\s+)?function\s+([A-Za-z_]\w*)\s*\(', src):
            name, start = m.group(1), m.end()
            i = src.find('{', start)
            if i < 0: continue
            depth, j = 0, i
            while j < len(src):
                if src[j] == '{': depth += 1
                elif src[j] == '}':
                    depth -= 1
                    if depth == 0: break
                j += 1
            if re.search(r'(?<![\w.])' + re.escape(name) + r'\s*\(', src[i:j]):
                line = src[:m.start()].count('\n') + 1
                print(f'[自递归] {p}:{line} {name}()')
```

## 八、未验证 / 已知限制

- **未做端到端实机运行**（用户明确要求不要启动服务，以免干扰其正在使用的旧实例）。

- **需要重新打包才能在发布版生效** —— `release/` 中的 exe 是 2.0.3 编译产物。

## 九、排查方法论教训

1. **用户描述的现象与用户的归因可能不一致。**
   用户说「换 `.env` 后坏掉」，把因果归到 `.env`；实际是同时升级了版本。
   应独立验证「现象」与「归因」，不要直接接受归因。

2. **编译通过 ≠ 运行正确。**
   `tsc --noEmit` EXIT=0 曾被我当作「改动安全」的依据，但自递归恰恰逃过了类型检查。
   涉及「函数包装/代理/重命名」时，必须人工确认内部调用的是**目标函数**而非自身。

3. **优先在「所有请求的必经之路」上找问题。**
   「整个应用用不了」这种全局症状，根因通常在公共层（统一请求封装、路由、初始化），
   而不是某个具体功能。

## 十、附带发现（独立问题，与本次崩溃无关）

| `.env.example` 缺 `WEBSPEECH_LANG` | 代码在 `monitor_router.py:63` 读取该键（默认 `zh-CN`），但示例文件未列出；同时示例中 ASR 模式注释也未包含 `webspeech` |
